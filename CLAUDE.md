# pm-cli

Local task tracker. Data: `~/.claude/pm/<project-slug>/`, binary: `pm`.

## Build

```
make install              # build + install (uses VERSION from Makefile)
make check                # gofmt-check + vet + staticcheck + go test ./...
make test-race             # go test -race ./... (also run by CI, not part of check)
make install VERSION=X.Y.Z  # override version
```

Git hooks live in `githooks/` (versioned; `git config core.hooksPath githooks` - already set locally). `pre-commit` just runs `make check`, so the hook, `make check`, and CI share one target set and can't drift apart. `staticcheck` is resolved via PATH → `go env GOBIN` → `GOPATH/bin` and fails with an install hint when missing (`go install honnef.co/go/tools/cmd/staticcheck@latest`). Fix failures - never bypass with `-n`.

CI (`.github/workflows/ci.yml`) runs on push to `main` and on every PR: `make fmt-check`, `make vet`, `make staticcheck`, `make test-race` - the same Makefile targets used locally, plus the race detector (deliberately not part of `make check`, which stays fast for the local commit-time gate).

IMPORTANT: Always use `make install` (not raw `go install`). Version is set via ldflags in Makefile. Bump `VERSION` in Makefile on each release. Current: **0.56.0**. Binary goes to `~/.local/share/go/bin/pm` (GOBIN).

## Tests

```
go test ./internal/... -v          # all tests
go test ./internal/storage/ -v     # single package
go test ./internal/storage/ -run TestSlugify -v  # single test
```

Always add tests when implementing new features or fixing bugs. Conventions:
- Go stdlib `testing`, table-driven tests, `t.Run("case", ...)` subtests
- `t.TempDir()` for I/O tests (auto-cleanup)
- Same package tests (access to unexported functions)
- `setupTestStore(t)` helper in `store_test.go` for tests needing a Store with project + tasks
- Invariant tests (links merge, Log append, Spec rewrite, brief lifecycle) live in `tools_test.go`; the `ApplySpec`/`ExtractSpec` unit tests live in `internal/storage/spec_test.go`
- **Executor paths**: test through a FAKE `claude` binary (`fakeClaude` in `internal/cmd/work_exec_test.go` - a PATH-prepended script emitting a canned result envelope), never by spending tokens; covers verified/blocked/crash/garbage paths of `executeWork` (the envelope's green word was `merged` before 0.34.0 and is still accepted - `normalizeWorkerStatus`)
- **MCP handlers**: test END-TO-END via the SDK in-memory transport (`startMCP` in `internal/mcpserver/e2e_test.go`) so the real registered closures run - do NOT re-simulate handler logic in the test body (the pre-0.23 tests did, which is why coverage sat at 12%)
- **Concurrency**: lock/race invariants live in `internal/storage/lock_test.go` + the `TestAcquireWorktreeLockAtomicRace` two-acquirer hammer in `worktree_test.go`; run suspects under `-race`

## Verification

- After code changes: `make check` (runs fmt-check + vet + staticcheck + test); run `make test-race` too before pushing anything touching concurrency/locking
- After TUI changes: `make install` + run `pm board` and test interactively
- After MCP changes: `make install` + test with `pm_context` / `pm_list_tasks` in Claude Code

## Key patterns

- **Frontmatter tasks**: `.md` file with YAML frontmatter (id, title, status, created, updated, status_changed, links, branch, parent, tags, brief, ac, waiting_for, order, sessions, depends_on, mode, model, epic_mode, finish_mode) + markdown body
- **Blocker fields** (`waiting_for` + `status_changed`): `waiting_for` is free text naming who/what a task is blocked on - unvalidated, never required (not even on `waiting`), tri-state over MCP like `brief`/`ac`. `status_changed` is an RFC3339 stamp of the last REAL status change, written by `Task.SetStatus` (`internal/storage/task.go`) - the one place that stamps it ON A MUTATION, so `Store.MoveTask` (every TUI/CLI/executor move) and MCP `pm_update_task` (which writes the task itself) share one rule. SetStatus is a no-op when the status is unchanged: re-stamping a move-to-the-same-status would reset the "stuck since" clock the field exists to report. The other two write sites are the CREATION ones - `NewTask` and the board's add literal (`update_menus.go`), which cannot use NewTask - and both take `updated` and `status_changed` from ONE `Now()` call, so a new task can never carry a status stamp a second later than its edit stamp. Nothing ever clears `waiting_for`: it is leftover text on a task that has moved on, not a live blocker. The board's undo (`doUndo` in `actions.go`) is the one status change that deliberately does NOT re-stamp - it restores the snapshot wholesale, stamp included, which is what undoing a move means. Files are never migrated, so it is EMPTY on older tasks - readers render that as unknown and never fall back to `updated`, which moves on any edit.
- **Task stamps** (`internal/storage/stamp.go`): `created` is a date (`storage.Today()`, `YYYY-MM-DD`); `updated` is a full local-zone RFC3339 timestamp (`storage.Now()`) so tasks touched the same day still order "most recent first". Files are NEVER migrated, so every reader tolerates both shapes: parse with `storage.ParseStamp` (RFC3339 or bare date, local zone), display a human date with `storage.StampDate`. Sorting still compares the raw strings (`LessByOrder`, the board columns, the picker's `lastUpdated` max in `update_picker.go`, MCP `tools.go:318/1053/1142`) and a bare date sorts before the same day's timestamps, which is the accepted trade for not migrating a thousand files - but it is only exact WITHIN one utc offset, so two stamps written either side of a DST switch can invert by up to an hour. Comparators that parse (`SortRunRows`) are exact. MCP returns the RAW `updated`, TUI/CLI display the date - and both display paths (`StampDate`, `relativeTime`) answer "which day" in the READER's local zone. The field stays a `string` so the stamp round-trips byte-exact instead of becoming a yaml `!!timestamp`.
- **Parent/subtask rollup**: `parent` in frontmatter makes a task a child of a tracker (derived: a task is a tracker iff another task names it as parent). `storage.BuildTrackers` generates the rollup used by `pm_context`/`pm context` - never hand-maintain status tables in the parent body. Lifecycle `todo → doing → merged|pushed → done`; children sort by `storage.LessByOrder` (shared with the board columns and the TUI tracker list); set `order` via MCP, `pm add --order`, or `pm reorder`. (history: docs/design-log.md)
- **Brief field**: `brief` in frontmatter stores short session context ("where we left off"). Overwrites on each update (not append). Preserved on all status transitions (including done/archived - useful for summaries/reverts). Returned by `pm_context` for doing tasks.
- **AC field**: `ac` in frontmatter stores acceptance criteria. Overwrites on each update (same as brief). Preserved on all status transitions. Returned in `pm_context` and `pm_list_tasks` summaries. When executing a task, constrain work to AC - don't add unrequested features or deviate from stated criteria.
- **Spec / Log body zones**: two zones, opposite write rules (solves append-only-rot). **Spec** = current truth between `<!-- spec:start/end -->` markers, rewritten wholesale via `storage.ApplySpec(body, spec)` (`internal/storage/spec.go`; `ExtractSpec` reads it); everything outside = append-only **Log** (`body_append`). If markers are absent when `spec` is first set, a block is prepended and the existing body becomes the Log. The TUI renders the markers as visible headers (`bodyToDisplayMarkdown` in `view_detail.go`). Canonical flow: rewrite Spec + append a one-line pointer to the Log.
- **Concurrency (lost-update protection)**: `Store.LockProject(slug)` (internal/storage/lock.go) is a cross-process flock on `<projectDir>/.pm.lock` - hold it around FindTask -> mutate -> WriteTask and re-read the task FRESH inside (wired into the mutating MCP handlers, `pm add`, `pm reorder`, `applyWorkerResult`/`recordSubFeedback`, and `Store.MoveTask`, which self-locks and treats the fresh re-read as a PRECONDITION: a vanished task is an error, no write). Never nest LockProject in one process; partial project.yaml edits go through `Store.MutateProject(slug, fn)`; `LockProject` errors on a missing project dir, never creates it. (history: docs/design-log.md)
- **Identifiers are PATH COMPONENTS, validated at the store**: `storage.ValidateTaskID` in `Store.AddTask` (before the O_EXCL claim), `storage.ValidateSlug` in `Store.CreateProject` (before MkdirAll), `storage.ValidateProjectPrefix` in create/update/mutate (only when the value CHANGES). `ValidateTaskID` is deliberately wider than `ValidateSlug` (digits-only/uppercase legal; spaces/non-ASCII rejected). (history: docs/design-log.md)
- **`pm work`/`pm run-epic` one-arg resolution** (pm-cli-74-1): the one-arg form scans projects in `FindTask`'s three tiers (exact ID -> unique ID prefix -> title substring), each tier deciding alone, ERRORING with candidates on a cross-project tie; cwd is a tiebreak INSIDE a tier, never a short-circuit; archived projects excluded unless you stand in one. (history: docs/design-log.md)
- **Project config**: `~/.claude/pm/<slug>/project.yaml` — name, path, repo, stack, notes, links, tags, statuses, `group`, `archived`. Writes go through `writeProject` (0.29.2): the fresh marshal is MERGED into the existing YAML node tree - comments and unknown top-level keys in a hand-tuned file survive (unchanged subtrees keep their original nodes), cleared known fields drop - and the file is written atomically (tmp+rename). `pm executor init` re-running over an annotated executor block no longer destroys the annotations.
- **Project groups + asleep = `archived`** (pm-cli-118-12): `group:` in project.yaml (a slug, `storage.ValidateGroup`, validated on create and on a CHANGE in `MutateProject` like the prefix) joins several repos into ONE cockpit project (ACME = acme-api + acme-zap + ...); a project with no `group` is a group of its own under its slug (`Project.GroupSlug`). `Store.ProjectGroups` DERIVES the groups from the active projects (no membership list anywhere); `archived: true` is THE asleep flag - an archived project is in no group and no cockpit aggregation, and the board's `hidden_projects` (tui-config.yaml) is UI state that is never read as a fact. The TUI/CLI ignore `group` and `writeProject` preserves it (it is a KNOWN key now). `service.ListProjects`/`pm_list_projects`/`/api/projects` carry `group` + `group_name`; `pm_create_project`/`pm_update_project` take `group` (tri-state on update); `service.ListGroups` = `/api/groups`.
- **Global `config.yaml` `cockpit:` block** (`internal/storage/cockpit.go`): every cockpit setting in one place next to `remotes` - `groups` (slug -> display name), thresholds (`doing_idle_days` 7, `waiting_highlight_days` 5, `stuck_project_days` 14), `cutoff_hour` (18), `refresh` (`every: 30m`, `window: 07:00-20:00`, `RefreshConfig.InWindow(now)` for the scheduler), `sections`/`sources` toggle maps over the CLOSED lists `CockpitSections`/`CockpitSources` (an unknown name is a load ERROR, never a silent no-op), `sidebar` (`variant` columns|plain|rail, `show_repos`, `sort` worst|last_activity|manual, `width`). `LoadConfig` decodes the file OVER `DefaultCockpitConfig()`, so an absent key keeps its default and an explicit zero wins (no pointer fields); no file/no block = defaults, an unparsable or invalid file = a loud error naming the key. This file owns type + defaults + parser + validation only; the MEANING of each field belongs to the consumer (attention aggregation, change feed, SPA). `Store.SaveConfig`/`MutateConfig` are the first writers of config.yaml: merged into the existing node tree (`mergeYAMLDocuments`, the `writeProject` mechanism), comments and unknown keys kept, validated BEFORE the write, the cockpit block written as resolved (defaults become explicit keys on the first save), no lock. `pm config show` prints the block resolved.
- **Statuses are per-project** (`Store.GetProjectStatuses(slug)`; default `[todo, doing, waiting, done]`, override in `project.yaml`; the ALL view merges all projects'). Every mutation path validates: `Store.MoveTask` and the MCP `status` params reject a status outside the project's set (`archived` always legal); `pm run-epic` hard-gates an unlisted `done_status` at run start. (history: docs/design-log.md)
- **Archive is system-level** — `StatusArchived` is NOT a project status. Never add to `DefaultStatuses` or `project.yaml`. `filteredTasks()` excludes archived. `Ctrl+a` toggles archive view.
- **TUI has 7 views** (`view` enum in `internal/tui/board/types.go`): `viewBoard`, `viewDetail`, `viewArchive`, `viewProjectInfo`, `viewFocus` (focus mode, entered in `update.go`), `viewExecutor` (the live agent-view, entered from `executor_view.go`), `viewRuns` (cross-project run list, `R`). `previousView` controls where detail/escape returns to; `viewExecutor` and `viewRuns` use their OWN `executorPrevView`/`runsPrevView` so opening them does not clobber detail's.

## Debugging TUI layout

When fixing layout/rendering bugs, don't guess at line counts - instrument (colored section markers, a debug status bar with `h`/`curH`/`mch`, a `-dbg` version suffix) and have the user screenshot; remove all debug code before committing. Key formula: a view's total visual lines = `strings.Count(output, "\n") + 1` and MUST equal `m.height`, or bubbletea cuts off the top. `maxCardHeight` = `m.height - overhead` (the per-line height budget and instrumentation recipe: docs/design-log.md); column content is clamped to exactly `maxCardHeight` newlines so `JoinHorizontal` stays consistent.

## Gotchas

- **Headless executor workers cannot write anywhere under `~/.claude`** (CC sensitive-path guard; `claude -p` has no one to approve the prompt, so it is a hard refusal, unlike an interactive session which just asks). That is why the source lives in `~/repos/pm-cli` while the data dir stays in `~/.claude/pm/` - and why a worker task that needs to write into the data dir will fail.
- **Headless workers run with `--strict-mcp-config`**: user-scope MCP is invisible to them (a project `.mcp.json` is passed back in); skills unaffected; `userMCP=true` in `buildClaudeArgs` restores it.
- `storage.DefaultStatuses` is the single source of truth for defaults - don't hardcode `[todo, doing, done]` elsewhere
- `ParseStatus` returns `TaskStatus`, not `(TaskStatus, error)` - it lowercases any string
- Task files live next to `project.yaml` in the same dir (not in a subdirectory)
- Links is `map[string]string` (freeform key=url), not a typed struct
- Version is set via ldflags at build time (`internal/version/version.go`) - defaults to "dev" without ldflags
- `cardHeight()` is a reference estimate only - `fixScrollOffsets` and `viewBoard` render cards and measure the actual `\n` count (text wrapping).
- **Task reorder**: `Ctrl+j/k` swaps task order within a column via `Order int` field in TaskMeta. If all tasks have `Order==0`, sequential orders are assigned first. `filteredTasks()` sorts by Order asc, then Updated desc.
- **Sessions**: `Sessions []string` in TaskMeta stores Claude session IDs (appended by TUI on launch, or via MCP `sessions` param). Used for `--resume` and `session_count` in MCP output. MCP `pm_get_task` returns full `sessions` list; `pm_update_task` and `pm_add_task` accept `sessions` param (append-only).
- **Session detection**: `pm session-id` prints current CC session UUID. Strategy: (1) walk process tree for `claude --resume <id>` arg, (2) fallback to newest .jsonl in `~/.claude/projects/<encoded-cwd>/`. Requires `CLAUDECODE=1` env var.
- **Worktree naming**: `worktreeName(t)` uses `t.Meta.Branch` if set, otherwise `Slugify(t.Meta.Title)`. Produces semantic branch names (e.g. `feat/enable-analytics` not `atlas-9`).

## Workflow

- Branch: substantive work (features, fixes, refactors, review-fix batches) goes on a feature branch and merges via PR, per repo history (`git log --merges`). Small standalone tweaks may still land as a direct commit on `main`.
- Commit messages: imperative, concise, prefix with feat/fix/refactor

## MCP server (`pm mcp`)

Stdio MCP server for Claude Code. Registered as user-scope MCP: `claude mcp add --transport stdio --scope user pm -- ~/.local/share/go/bin/pm mcp`.

- **Package**: `internal/mcpserver/` — `server.go` (setup + Run), `tools.go` (10 tools), `journal.go` (`registerJournalTools`, 2 tools) = **12 registered tools**
- **Every tool's semantics live in `internal/service`; the 12 MCP handlers are thin** (pm-cli-118-3/-4): `service.AddTask/UpdateTask/MoveTask/DeleteTask` (mutations: status validation, tri-state, link merge, Spec/Log, `LockProject` with the FRESH re-read, the load-bearing mode/epic_mode/finish_mode pre-checks), `ListTasks/GetTask/Context` (+`ProjectContext`/`CrossProjectContext`), `ListProjects/CreateProject/UpdateProject` (slug/prefix validation, `validateStatusesKeepTasks`), `JournalAdd/JournalList` - all over `storage.TaskStore`. The handlers only decode -> call -> `respond` (`jsonText`/`toolError`), and the coming `pm serve` HTTP API calls the same functions. DTOs are exported service types in `internal/service/dto.go` (`TaskSummary`, `TaskDetail`, `ListTasksResult`, `ProjectContextResult`, `CrossProjectContextResult`, `ListProjectsResult`, `ProjectResult`, `JournalEntriesOutput`, `JournalAddResult`) with the json tags that ARE the agent contract; where a shape used to be a `map[string]any`, the struct's field order is the map's alphabetical key order so the wire bytes did not change (diffed before/after on a fixed store, schemas included). The argument structs (`service.AddTaskInput` etc., `jsonschema` tags included) are the ONE copy of every parameter description - `tools.go`/`journal.go` alias them, so the generated tool schemas did not change. Output budgets (`DefaultListLimit`/`MaxListLimit`/`ContextBodyLimit`, `DefaultJournalLimit`/`MaxJournalLimit`) are service constants. Caller-caused failures are `*service.ValidationError` (unwrap to the underlying error); the package must never import the MCP SDK. Unit tests in `internal/service/*_test.go`; the e2e MCP tests remain the behaviour proof. (history: docs/design-log.md)
- **Subcommand**: `internal/cmd/mcp.go` — `pm mcp` cobra command
- **SDK**: `github.com/modelcontextprotocol/go-sdk/mcp` — typed `AddTool[In, Out]` for auto schema generation
- **Tools**: `pm_context`, `pm_list_tasks`, `pm_get_task`, `pm_list_projects`, `pm_add_task`, `pm_update_task`, `pm_update_project`, `pm_create_project`, `pm_move_task`, `pm_delete_task` (all in `tools.go`), plus `pm_journal_list`, `pm_journal_add` (in `journal.go`, added 0.35.0)
- **No MCP resources** (pm-cli-72-3): removed - each duplicated a tool with a worse copy and bypassed the output budgets. Use `pm_list_projects`, `pm_list_tasks`, `pm_get_task`/`pm_context`. (history: docs/design-log.md)
- **CWD auto-detection**: `pm_context` with `cwd` param matches against project.yaml `path` fields
- **Output budget** (0.24.0): `pm_list_tasks` returns the 50 newest tasks (`limit` overrides) as `{tasks, total, shown, note}` with ONE-LINE briefs (`storage.BriefLine`; `ac` stays full); `pm_context` caps each doing-task `body` at 2000 runes but never truncates `brief`; `pm_get_task` is unbounded. Tracker briefs are one line (`brief_line`) and a finished tracker collapses its children (`children_omitted: true`); the project-scoped `doing_tasks` brief stays FULL on purpose. (history: docs/design-log.md)
- **Attention aggregation** (pm-cli-118-13, `internal/storage/attention.go`): ONE cross-project queue of what needs the human, computed in storage (`BuildAttention(store, cfg, opts)`) and consumed by three surfaces off the same value - `/api/attention` (`service.Attention`, `?project=`/`?group=` via `Attention.Scope`), `pm today` (`--json` = the API shape; `internal/cmd/today.go`), and the `attention` block of `pm_context` (`service.DigestAttention`: needs_me + stuck_projects in full, waiting capped at `ContextWaitingLimit` 10 with `no_reason` rows promoted, every other enabled section as a count; best-effort - a config error is a note, never a failed context). Inputs are LOCAL FILES ONLY (tasks of non-archived projects, `.executor/` run/finish states + claims, focus.yaml, `group`, the `cockpit:` block); the `changes` section only EMBEDS a `ChangesDigest` the caller hands in (118-14), never fetches. Sections in `CockpitSections` order, each on/off from `cockpit.sections`, a disabled one is NOT emitted. `needs_me` ranks (a) run failed / crashed (= run-state `running` with a dead pid) › (b) acceptance failed/crashed › (c) open visual claims › (d) run done with no acceptance and no claim › (e) acceptance partial › (f) live claim (checked BEFORE the acceptance state, the acceptCell rule), oldest first within a rank. `waiting` ages come from `status_changed` ONLY (empty = `age_seconds: null`, "since ?" - never `updated`); `stuck_projects` uses activity = max(updated, status_changed) on purpose (rule 1: no task change for `stuck_project_days`; rule 2: >=1 doing task, every doing task idle `doing_idle_days`, nothing on focus). `focus` carries an older plan over (`Cleanup` semantics against the INJECTED clock, flag `stale_plan`). Rows share one shape with a closed `actions` set decided by the row's state (`ActionOpen`..`ActionOpenPR`) - a UI renders, never invents; `GroupSummary` = worst severity + failed/visual/waiting/quiet counters + last_activity, sorted worst-first. `wip` = doing tasks with activity since Monday. `recent` is configurable but NOT computed (the session-file lookup lives in the TUI); its section says so in `note`. Tests: `attention_test.go` fixture covers every AC case with a fixed clock (`AttentionOptions.Now`).
- **Trackers rollup**: `pm_context` returns a `trackers` section (parent+subtask rollup) when any task has children. Children/trackers are suppressed from the flat `doing_tasks` list. `pm_add_task`/`pm_update_task` accept a `parent` param. Same rollup is available offline via the `pm context [project]` CLI command (`internal/cmd/context.go`) - useful when the running MCP holds a stale binary.
- **Executor fields over MCP** (0.26.0; `finish_mode` 0.41.0): `pm_get_task` returns `model`, `epic_mode` and `finish_mode`; `pm_add_task`/`pm_update_task` accept `epic_mode` and `finish_mode` (update: omit = keep, `""` = clear - the `mode`/`model` pattern). Validation is enforced in `writeTask` (`storage.ValidateEpicMode`/`ValidateFinishMode`, like `ValidateMode`); the handler-level pre-checks are LOAD-BEARING, not cosmetic - a writeTask failure after the O_EXCL claim would leave a 0-byte phantom file (pm-cli-41).
- **Invariants**: links merge (never remove); `body_append` appends to the Log; `spec` rewrites the Spec block in place; tags replace if provided. `branch`/`parent`/`brief`/`ac`/`waiting_for` are tri-state on `pm_update_task` (omit = keep, `""` = clear); `title` is never clearable. `status_changed` is never a param - pm stamps it itself on a real status change. `status` params reject values outside the project's set (`archived` always legal); `pm_update_project` rejects a `statuses` replacement that would orphan tasks (an empty list resets to defaults and is checked against THAT set); `pm_create_project` validates `slug` via `storage.ValidateSlug`. (history: docs/design-log.md)

## Web (`pm serve`) — read-only HTTP face of the cockpit

`pm serve --addr 127.0.0.1:7070` (`internal/cmd/serve.go`) serves `internal/server` (pm-cli-118-5): stdlib `net/http` with Go 1.22 method+pattern routing, NO framework, no auth, no TLS (localhost; remote access = Tailscale). (history: docs/design-log.md)

- **Package map**: `server.go` = `NewHandler(store, Options)` + the JSON endpoints + the SPA handler; `events.go` = the SSE feed; `dist/` = the go:embed'd bundle (only `.gitkeep` is versioned - `make web` fills it, `.gitignore` keeps it out). `Options` = `Static fs.FS` (tests pass an `fstest.MapFS`), `RemoteRuns` hook, `PollInterval`/`PingInterval` (defaults 2 s / 15 s).
- **Read-only, and the DTOs are the service's**: `/api/projects` (ListProjects rows + path/repo/tags/links/statuses/landing_statuses; `group`/`group_name`/`archived` ride on the ProjectInfo), `/api/groups` -> `service.ListGroups` (loud 500 on a broken config.yaml, where `/api/projects` only notes it), `/api/attention[?project=|?group=]` -> `service.Attention` (the whole `storage.Attention`, its `changes` section embedding the feed cache's digest; 500 on a broken config - the thresholds ARE the queue's definition), `/api/changes` + the two POSTs (below), `/api/tasks` -> `service.ListTasks`, `/api/tasks/{project}/{id}` -> `service.GetTask`, `/api/context` -> `service.Context`, `/api/runs` -> `storage.LocalRunRows` (+ the injected remote fetch ONLY on `?remote=1` - an ssh round-trip per runner is never the default a dashboard polls), `/api/focus` -> `storage.ReadFocusPlan` + `service.FocusTaskSummaries`. Never define a second copy of a DTO here. Every route is `GET`-qualified so the mux answers a POST with 405 itself.
- **Errors** are `{"error": "..."}`: `*service.ValidationError` -> 400, `storage.ErrTaskNotFound`/`ErrProjectNotFound` -> 404 (sentinels wrapped into FindTask/FindTaskExact/ResolveProject with the messages unchanged), `storage.ErrAmbiguousTask` -> 400, anything else 500; an unknown `/api/*` path is a JSON 404, never the SPA.
- **Change feed (`internal/feed`, pm-cli-118-14)** - "what changed since yesterday 18:00" from SOURCES behind one interface (`feed.Source`: `Name()` + `Fetch(ctx, from, to, projects) ([]Event, error)`; a per-project failure is a `*ProjectError` joined with the other projects' events); the registry is `feed.Sources(root, runner)` = `pm` (status_changed, created on/after the cutoff's DATE, executor journal start/end/killed/crashed, acceptance run-states, the focus plan - zero network), `git` (commits on every branch a task names via `git log --since/--until` in the project's `path` - a branch that does not exist locally is skipped, `AllBranches` widens it to `--all`; open PRs via `gh pr list --json`), `github` (comments + reviews + decision via `gh pr view --json` for the open PRs touched in the window only). A new source = one file + one registry line. `Event.ID` is STABLE (`feed.EventID(parts...)`), which is what makes a refresh idempotent: the cache under `<pm-root>/.cockpit/changes/` (JSONL per event day, the journal's grain; `state.json` = source statuses + the `seen` stamp; 14-day rotation) dedups on it and holds ONLY in-window events. `Feed.Refresh` runs every ENABLED source (`cockpit.sources`), records each one's `SourceStatus{last_fetch, error, events}` and NEVER lets one source's failure stop the others; `Feed.Read(cutoff)` applies the seen flag from the cache alone; `Feed.Digest`/`feed.ReadDigest` shape the cache for the attention queue's `changes` section (unseen count + newest unseen rows) - the aggregation never fetches. External commands go through a `feed.Runner` (`DefaultRunner`: own process group, `feed.CommandTimeout` 30 s, group SIGKILL on expiry, pagers/prompts disabled; `pm serve` injects `feedRunner` built on `groupCmd`); tests fake `gh` and run real `git` on a temp repo. The cutoff is `feed.Cutoff(cfg, now)` = `storage.CutoffSince` (before 18:00 -> yesterday 18:00, else today 18:00).
- **Feed endpoints + scheduler** (`internal/server/changes.go`): `GET /api/changes` (cache: `{cutoff, events[] with seen, unseen, seen, sources[]}`), `POST /api/changes/refresh` (runs the sources NOW whatever the window says, 5-min outer wall, answers the `feed.Result`), `POST /api/changes/seen` (`{ts}` optional, default now); each of the two POSTs publishes the SSE `event: changes` (`data: {"sources":[...]}`) through a `changeBus` fan-out every open `/api/events` stream subscribes to (non-blocking send; a missed signal is caught by the next). `NewHandler` now returns `*server.Handler` (an http.Handler) with `RunScheduler(ctx)`: every `cockpit.refresh.every` (re-read per tick; 0 = off) it calls `schedulerTick`, which refreshes ONLY when `RefreshConfig.InWindow(clock())` - outside 07:00-20:00 nothing reaches git/gh unasked. `Options.Clock` injects the clock (the window test runs at 12:30 and 22:30 without waiting), `Options.Feed` the feed (tests hand in fake sources). A GET on a POST-only route is the `/api/` catch-all's JSON 404, not a 405.
- **SSE says WHAT changed, never what to** (`event: tasks|runs`, `data: {"project": slug}`; `event: changes`, `data: {"sources": [...]}` after a feed refresh or a seen mark; `event: ping` while idle): a fixed-interval poll fingerprints each active project from directory METADATA only (names/sizes/mtimes of `*.md` + `project.yaml`, and of `.executor/*.json` + `*.claim`) - no file content, no fsnotify (zero new deps, and the board already lives on a 2 s tick). The handler returns on `r.Context().Done()`, which is what lets `Shutdown` finish. A heartbeat re-stamping a live run-state is a `runs` event every 30 s per live run - by design, the client refetches `/api/runs`.
- **SPA**: `//go:embed all:dist` - the `all:` prefix is load-bearing (without it a dot-file-only dir embeds nothing and the build fails). A path naming a file is served (`assets/*` = `immutable` cache, Vite hashes the names; anything else `no-cache`); everything else gets `index.html` with `no-store`; no `index.html` at all = a built-in placeholder page saying "run `make web`", with 200 (a 404 would read as "server down").
- **The remote-runs ssh fetch stays in `internal/cmd`** (`remoteRunRows`, which needs `groupCmd` and the test-patched `remoteRunsTimeout`) and is injected via `Options.RemoteRuns` - `internal/server` must never import `internal/cmd` (cycle), and `pm runs` output is untouched.
- **Tests** (`internal/server/server_test.go`): `httptest` over the same temp-store fixture the MCP e2e uses; every endpoint, the error codes, `?remote=1` through a fake hook (never ssh), the placeholder/bundle/fallback/cache-header matrix, and the SSE feed end to end (ping, a task edit -> `tasks`, a run-state file -> `runs`, cancel -> handler returns and `Close` does not hang).
- **The SPA lives in `web/`** (pm-cli-118-6): npm (`package-lock.json` versioned), Vite + React + TypeScript `strict`, Tailwind v4 (utility classes on native HTML elements only - no component library, no design system until the visual pass, pm-cli-118-10), `@tanstack/react-query` + `@tanstack/react-router` (code-based routes in `src/routes/router.tsx` - three routes do not justify the file-based plugin), oxlint + prettier (the current Vite template ships oxlint, not eslint), vitest + testing-library (jsdom). - **Make targets**: `web-install` (`npm ci`), `web-check` (lint + typecheck + vitest, what CI's `web` job runs), `web` (bundle), `install-full` (`web` + `install`). `check` and `install` are NODE-FREE on purpose - the pre-commit hook must stay fast and `go build` works with an empty `dist/`.
- **Layer boundary - what makes the UI replaceable, enforce it in review**: `web/src/api/` (`types.ts` = hand-written mirrors of the Go DTOs' json tags, `client.ts` = the fetch wrapper + `ApiError{status}`, `queries.ts` = react-query hooks with the KEYS `['projects']`, `['tasks', slug]`, `['task', slug, id]`, `['context', slug]`, `['runs']`, `['focus']`) and `web/src/lib/` (pure functions, no React, each with a vitest test) are PERMANENT. `web/src/routes/` (composition: hooks in, components out) and `web/src/components/` (props in, JSX out - no `fetch`, no `useQuery`, no grouping/sorting/counting) are REPLACEABLE: the visual pass swaps those two dirs and touches nothing else. ## Journals (`pm journal`) — per-project record of a flaky subsystem

A **journal** is a per-project append-only record of how ONE declared, repeatedly-troublesome subsystem actually behaves (0.35.0, pm-cli-83). Which subsystems a project journals is declared in `project.yaml` `journals:` (name + one-line subject); an undeclared name is an error, never an implicit create. (history: docs/design-log.md)

- **RULE vs EVENT**: a memory file or doc holds the RULE (current truth, rewritten); a journal entry holds an EVENT (dated, append-only, never rewritten); `fix` NAMES the rule it produced. Empty `fix` = OPEN, and the open set IS the backlog (derived, never hand-maintained). (history: docs/design-log.md)
- **Storage** (`internal/storage/journal.go`): JSONL per subject at `<projectDir>/.journal/<name>.jsonl`; `Incident` = `{ts, symptom, false_conclusion, cause, cost_min, fix, tags, session}`; `AppendIncident` RETURNS its write error. (history: docs/design-log.md)
- **Agnostic by config**: `Project.Journals` is the whole of the mechanism's project-awareness - nothing in the code knows what a simulator is. A journal NAME is a file name (`ValidateJournalName` = the `ValidateSlug` rule); a typo'd name would silently open a second file and split one history in half - hence undeclared-is-an-error in both CLI and MCP.
- **Closing an entry is a new EVENT, never an edit** (0.36.0): `Incident.Resolves []string` closes earlier entries (`StillOpen` = no own `fix` AND not resolved later); an unknown `resolves` id is REJECTED before the write; ids are DERIVED (`incidentID`), so pre-existing lines are closable. (history: docs/design-log.md)
- **Ordering**: entries read newest-first; an entry whose `ts` does not parse sorts LAST; `JournalStats.First/Last` come off the PARSED instant. (history: docs/design-log.md)
- **The cost average divides by `Costed`, not `Total`** - entries that recorded a cost. Dividing by the total would make a subsystem look CHEAPER the more often someone skipped the field, i.e. exactly backwards.
- **Surfaces**: `pm journal list|show|add|stats` (CLI, `--project` flag) and `pm_journal_add`/`pm_journal_list` (MCP); add reports back the recurrence its entry produced; stats travel WITH the entries. (history: docs/design-log.md)
- **`pm_context` / `pm context` get COUNTS ONLY**, never content (same rule as the executor profile pointer, 0.28.1): a journal grows without bound and its readers are the sessions about to touch that subsystem, not every session. No journals declared = no key at all.

## Executor (`pm work` / `pm run-epic` / `pm finish`)

Runs pm tasks/epics via isolated headless `claude -p` workers (implement -> test -> review -> verify). **The full internals live in `docs/executor.md`** (worktree slots, review policy, run-state/journal/heartbeat, kill + crash forensics, acceptance claims, baseline, independent mode, telemetry) - read it before touching `internal/cmd/work*.go`, `run_epic*.go`, `finish*.go`, `worker_guard.go` or `internal/storage/executor*.go`. The rules that bite regardless of what you are working on:

- **Headless workers cannot write under `~/.claude`** (CC sensitive-path guard, a hard refusal with nobody to approve) - source lives in `~/repos/pm-cli`, data in `~/.claude/pm/`.
- **Review is decided by pm, not the worker** (0.38.0): reviewer count, model (`executor.review_model`, default opus), packet (the whole diff) and rounds (`executor.fix_rounds`) are enforced by the `pm worker-guard` PreToolUse hook, which also blocks hook bypasses and `.git/` writes - in `--yolo` too.
- **Test executor paths through the fake `claude` binary** (`fakeClaude` in `internal/cmd/work_exec_test.go`), never by spending tokens; the envelope has two shapes (object, or a message array whose last element is the object - `decodeClaudeOutput`).
- **Every run journals itself** (`<project>/.executor/journal.jsonl`, append-only; `pm executor stats` is the rollup, `/executor-retro` the reader) - a new run-time fact belongs in the run-state + journal, not in a log line.
- **Tokens, not dollars, are what the subscription window meters** (0.55.0): per-sub `tokens` off the envelope's `usage`; workers run under `executor.worker_claude_config_dir` when set (a slim config dir without the user-scope skill catalogue / CLAUDE.md), and the worker prompt carries a call discipline (no prose between tools, batch independent calls) - see pm-cli-119.
