# pm-cli

Local task tracker. Data: `~/.claude/pm/<project-slug>/`, binary: `pm`.

## Build

```
make install              # build + install (uses VERSION from Makefile)
make check                # gofmt-check + vet + staticcheck + go test ./...
make test-race             # go test -race ./... (also run by CI, not part of check)
make install VERSION=X.Y.Z  # override version
```

Git hooks live in `githooks/` (versioned; `git config core.hooksPath githooks` - already set locally). `pre-commit` just runs `make check`, so the hook, `make check`, and CI share one target set and can't drift apart. `staticcheck` is resolved via PATH → `go env GOBIN` → `GOPATH/bin` and fails with an install hint when missing (`go install honnef.co/go/tools/cmd/staticcheck@latest`). Fix failures - never bypass with `-n`.

CI (`.github/workflows/ci.yml`) runs on push to `main` and on every PR: `make fmt-check`, `make vet`, `make staticcheck`, `make test-race` - the same Makefile targets used locally, plus the race detector (deliberately not part of `make check`, which stays fast for the local commit-time gate).

IMPORTANT: Always use `make install` (not raw `go install`). Version is set via ldflags in Makefile. Bump `VERSION` in Makefile on each release. Current: **0.39.0**. Binary goes to `~/.local/share/go/bin/pm` (GOBIN).

## Tests

```
go test ./internal/... -v          # all tests
go test ./internal/storage/ -v     # single package
go test ./internal/storage/ -run TestSlugify -v  # single test
```

Always add tests when implementing new features or fixing bugs. Conventions:
- Go stdlib `testing`, table-driven tests, `t.Run("case", ...)` subtests
- `t.TempDir()` for I/O tests (auto-cleanup)
- Same package tests (access to unexported functions)
- `setupTestStore(t)` helper in `store_test.go` for tests needing a Store with project + tasks
- Invariant tests (links merge, Log append, Spec rewrite, brief lifecycle) live in `tools_test.go`; the `ApplySpec`/`ExtractSpec` unit tests live in `internal/storage/spec_test.go`
- **Executor paths**: test through a FAKE `claude` binary (`fakeClaude` in `internal/cmd/work_exec_test.go` - a PATH-prepended script emitting a canned result envelope), never by spending tokens; covers verified/blocked/crash/garbage paths of `executeWork` (the envelope's green word was `merged` before 0.34.0 and is still accepted - `normalizeWorkerStatus`)
- **MCP handlers**: test END-TO-END via the SDK in-memory transport (`startMCP` in `internal/mcpserver/e2e_test.go`) so the real registered closures run - do NOT re-simulate handler logic in the test body (the pre-0.23 tests did, which is why coverage sat at 12%)
- **Concurrency**: lock/race invariants live in `internal/storage/lock_test.go` + the `TestAcquireWorktreeLockAtomicRace` two-acquirer hammer in `worktree_test.go`; run suspects under `-race`

## Verification

- After code changes: `make check` (runs fmt-check + vet + staticcheck + test); run `make test-race` too before pushing anything touching concurrency/locking
- After TUI changes: `make install` + run `pm board` and test interactively
- After MCP changes: `make install` + test with `pm_context` / `pm_list_tasks` in Claude Code
- After storage changes: verify task files in `~/.claude/pm/` have correct frontmatter

## Key patterns

- **Frontmatter tasks**: `.md` file with YAML frontmatter (id, title, status, created, updated, links, branch, parent, tags, brief, ac, order, sessions, depends_on, mode, model, epic_mode) + markdown body
- **Parent/subtask rollup**: `parent` in frontmatter makes a task a child of a tracker (derived: a task is a tracker iff another task names it as parent). `storage.BuildTrackers` generates the rollup used by `pm_context`/`pm context` - never hand-maintain status tables in the parent body. Lifecycle `todo → doing → merged|pushed → done`; children sort by `storage.LessByOrder` (shared with the board columns and the TUI tracker list); set `order` via MCP, `pm add --order`, or `pm reorder`. (history: docs/design-log.md)
- **Brief field**: `brief` in frontmatter stores short session context ("where we left off"). Overwrites on each update (not append). Preserved on all status transitions (including done/archived - useful for summaries/reverts). Returned by `pm_context` for doing tasks.
- **AC field**: `ac` in frontmatter stores acceptance criteria. Overwrites on each update (same as brief). Preserved on all status transitions. Returned in `pm_context` and `pm_list_tasks` summaries. When executing a task, constrain work to AC - don't add unrequested features or deviate from stated criteria.
- **Spec / Log body zones**: the body splits into two zones with opposite write rules, solving append-only-rot on long-lived tasks. The **Spec** zone (delimited by `<!-- spec:start -->`/`<!-- spec:end -->` markers, written via the `spec` param) is the current-truth document - rewritten wholesale in place via `storage.ApplySpec(body, spec)` (`internal/storage/spec.go`). Everything outside the markers is the append-only **Log** (written via `body_append`). `storage.ExtractSpec(body)` returns the Spec content. The TUI detail view renders the markers as visible `## Spec (current truth)` / `## Log (history, append-only)` headers (`bodyToDisplayMarkdown` in `view_detail.go`). Markers default to the top of the body (Spec first, Log below); if absent when `spec` is first set, a block is prepended and the existing body becomes the Log. Canonical flow: rewrite Spec + append a one-line pointer to the Log.
- **Concurrency (lost-update protection)**: `Store.LockProject(slug)` (internal/storage/lock.go) is a cross-process flock on `<projectDir>/.pm.lock` - hold it around FindTask -> mutate -> WriteTask and re-read the task FRESH inside (wired into the mutating MCP handlers, `pm add`, `pm reorder`, `applyWorkerResult`/`recordSubFeedback`, and `Store.MoveTask`, which self-locks and treats the fresh re-read as a PRECONDITION: a vanished task is an error, no write). Never nest LockProject in one process; partial project.yaml edits go through `Store.MutateProject(slug, fn)`; `LockProject` errors on a missing project dir, never creates it. (history: docs/design-log.md)
- **Identifiers are PATH COMPONENTS, validated at the store**: `storage.ValidateTaskID` in `Store.AddTask` (before the O_EXCL claim), `storage.ValidateSlug` in `Store.CreateProject` (before MkdirAll), `storage.ValidateProjectPrefix` in create/update/mutate (only when the value CHANGES). `ValidateTaskID` is deliberately wider than `ValidateSlug` (digits-only/uppercase legal; spaces/non-ASCII rejected). (history: docs/design-log.md)
- **`pm work`/`pm run-epic` one-arg resolution** (pm-cli-74-1): the single-argument form scans projects in `FindTask`'s three tiers (exact ID -> unique ID prefix -> title substring), each tier deciding alone, ERRORING with the candidates on a cross-project tie; the cwd project is a tiebreak INSIDE a tier, never a short-circuit; archived projects are excluded unless you stand in one. (history: docs/design-log.md)
- **Project config**: `~/.claude/pm/<slug>/project.yaml` — name, path, repo, stack, notes, links, tags, statuses. Writes go through `writeProject` (0.29.2): the fresh marshal is MERGED into the existing YAML node tree - comments and unknown top-level keys in a hand-tuned file survive (unchanged subtrees keep their original nodes), cleared known fields drop - and the file is written atomically (tmp+rename). `pm executor init` re-running over an annotated executor block no longer destroys the annotations.
- **Statuses are per-project** (`Store.GetProjectStatuses(slug)`; default `[todo, doing, waiting, done]`, override in `project.yaml`; the ALL view merges all projects'). Every mutation path validates: `Store.MoveTask` and the MCP `status` params reject a status outside the project's set (`archived` always legal); `pm run-epic` hard-gates an unlisted `done_status` at run start. (history: docs/design-log.md)
- **Archive is system-level** — `StatusArchived` is NOT a project status. Never add to `DefaultStatuses` or `project.yaml`. `filteredTasks()` excludes archived. `Ctrl+a` toggles archive view.
- **TUI has 6 views** (`view` enum in `internal/tui/board/types.go`): `viewBoard`, `viewDetail`, `viewArchive`, `viewProjectInfo`, `viewFocus` (focus mode, entered in `update.go`), `viewExecutor` (the live agent-view, entered from `executor_view.go`). `previousView` controls where detail/escape returns to; `viewExecutor` uses its OWN `executorPrevView` so opening it does not clobber detail's.

## Debugging TUI layout

When fixing layout/rendering bugs, don't guess at line counts. Add temporary instrumentation and have the user screenshot:

1. **Colored section markers** - add `lipgloss.NewStyle().Background(color).Render("[TAG]")` at section boundaries to see exactly where each section starts
2. **Debug status bar** - replace the status bar with key metrics: `h` (terminal height), `curH` (computed height), `pad` (padding lines), `mch` (max card height), per-column content line counts
3. **Key formula**: `viewBoard` total visual lines = `strings.Count(output, "\n") + 1`. Must equal `m.height`. If `curH > h`, top lines get cut off by bubbletea
4. **Build with `-dbg` suffix**: use version like `0.7.1-dbg` so debug builds are clearly identified
5. **Clean up**: remove all debug code before committing. Restore `version` import if status bar uses it

Layout height budget for `viewBoard` (each item = newlines contributed):
- Title with `Padding(0,0,1,0)` + explicit `\n`: 2
- Tabs + `\n\n`: 2
- Column border/padding (`Padding(1,2)` + `RoundedBorder`): 4
- Column content (cards): `maxCardHeight` (variable)
- `\n` after columns: 1
- Confirmation line (always reserved): 1
- Status bar (no trailing `\n`): 1 visual line
- Total = `maxCardHeight + 11` (+ 1 if search/add active)

The `maxCardHeight` is computed dynamically: `m.height - overhead` where overhead accounts for all non-column lines. Column content is clamped (truncated if over, padded if under) to exactly `maxCardHeight` newlines so `JoinHorizontal` produces consistent height across projects.

## Gotchas

- **Headless executor workers cannot write anywhere under `~/.claude`** (CC sensitive-path guard; `claude -p` has no one to approve the prompt, so it is a hard refusal, unlike an interactive session which just asks). That is why the source lives in `~/repos/pm-cli` while the data dir stays in `~/.claude/pm/` - and why a worker task that needs to write into the data dir will fail.
- `storage.DefaultStatuses` is the single source of truth for defaults - don't hardcode `[todo, doing, done]` elsewhere
- `ParseStatus` returns `TaskStatus`, not `(TaskStatus, error)` - it lowercases any string
- Task files live next to `project.yaml` in the same dir (not in a subdirectory)
- Links is `map[string]string` (freeform key=url), not a typed struct
- Version is set via ldflags at build time (`internal/version/version.go`) - defaults to "dev" without ldflags
- `cardHeight()` is an estimate for reference only - not used for scroll or rendering logic. Both `fixScrollOffsets` and `viewBoard` render cards and measure actual `\n` count to handle text wrapping correctly. Column content is clamped to `maxCardHeight` as a safety net.
- **Task reorder**: `Ctrl+j/k` swaps task order within a column via `Order int` field in TaskMeta. If all tasks have `Order==0`, sequential orders are assigned first. `filteredTasks()` sorts by Order asc, then Updated desc.
- **Sessions**: `Sessions []string` in TaskMeta stores Claude session IDs (appended by TUI on launch, or via MCP `sessions` param). Used for `--resume` and `session_count` in MCP output. MCP `pm_get_task` returns full `sessions` list; `pm_update_task` and `pm_add_task` accept `sessions` param (append-only).
- **Session detection**: `pm session-id` prints current CC session UUID. Strategy: (1) walk process tree for `claude --resume <id>` arg, (2) fallback to newest .jsonl in `~/.claude/projects/<encoded-cwd>/`. Requires `CLAUDECODE=1` env var.
- **Worktree naming**: `worktreeName(t)` uses `t.Meta.Branch` if set, otherwise `Slugify(t.Meta.Title)`. Produces semantic branch names (e.g. `feat/enable-analytics` not `atlas-9`).

- **Subcommand**: `internal/cmd/mcp.go` — `pm mcp` cobra command

- **No MCP resources** (pm-cli-72-3): removed - each duplicated a tool with a worse copy and bypassed the output budgets. Use `pm_list_projects`, `pm_list_tasks`, `pm_get_task`/`pm_context`. (history: docs/design-log.md)
- **CWD auto-detection**: `pm_context` with `cwd` param matches against project.yaml `path` fields
- **Output budget** (0.24.0): `pm_list_tasks` returns the 50 newest tasks (`limit` overrides) as `{tasks, total, shown, note}` with ONE-LINE briefs (`storage.BriefLine`; `ac` stays full); `pm_context` caps each doing-task `body` at 2000 runes but never truncates `brief`; `pm_get_task` is unbounded. Tracker briefs are one line (`brief_line`) and a finished tracker collapses its children (`children_omitted: true`); the project-scoped `doing_tasks` brief stays FULL on purpose. (history: docs/design-log.md)
- **Trackers rollup**: `pm_context` returns a `trackers` section (parent+subtask rollup) when any task has children. Children/trackers are suppressed from the flat `doing_tasks` list. `pm_add_task`/`pm_update_task` accept a `parent` param. Same rollup is available offline via the `pm context [project]` CLI command (`internal/cmd/context.go`) - useful when the running MCP holds a stale binary.
- **Executor fields over MCP** (0.26.0): `pm_get_task` returns `model` and `epic_mode`; `pm_add_task`/`pm_update_task` accept `epic_mode` (update: omit = keep, `""` = clear - the `mode`/`model` pattern). Validation is enforced at the storage layer (`storage.ValidateEpicMode` in `writeTask`, like `ValidateMode` for `mode`), with handler-level pre-checks that are LOAD-BEARING, not cosmetic (a writeTask failure after the O_EXCL claim would leave a 0-byte phantom file - see pm-cli-41). Lets `/batch-prep` set up an independent tracker entirely via MCP with a read-back confirm.
- **Invariants**: links merge (never remove); `body_append` appends to the Log; `spec` rewrites the Spec block in place; tags replace if provided. `branch`/`parent`/`brief`/`ac` are tri-state on `pm_update_task` (omit = keep, `""` = clear); `title` is never clearable. `status` params reject values outside the project's set (`archived` always legal); `pm_update_project` rejects a `statuses` replacement that would orphan tasks (an empty list resets to defaults and is checked against THAT set); `pm_create_project` validates `slug` via `storage.ValidateSlug`. (history: docs/design-log.md)

## Journals (`pm journal`) — per-project record of a flaky subsystem

A **journal** is a per-project append-only record of how ONE declared, repeatedly-troublesome subsystem actually behaves (0.35.0, pm-cli-83). Which subsystems a project journals is declared in `project.yaml` `journals:` (name + one-line subject); an undeclared name is an error, never an implicit create. (history: docs/design-log.md)

- **RULE vs EVENT**: a memory file or doc holds the RULE (current truth, rewritten); a journal entry holds an EVENT (dated, append-only, never rewritten); `fix` NAMES the rule it produced. Empty `fix` = OPEN, and the open set IS the backlog (derived, never hand-maintained). (history: docs/design-log.md)
- **Storage** (`internal/storage/journal.go`): JSONL per subject at `<projectDir>/.journal/<name>.jsonl`; `Incident` = `{ts, symptom, false_conclusion, cause, cost_min, fix, tags, session}`; `AppendIncident` RETURNS its write error. (history: docs/design-log.md)
- **Agnostic by config**: `Project.Journals` (`journals:` in project.yaml, name + one-line subject) is the whole of the mechanism's project-awareness - nothing in the code knows what a simulator is. A journal NAME is a file name, so `ValidateJournalName` gates it with the same `ValidateSlug` rule as project slugs (see "Identifiers are PATH COMPONENTS"). An **undeclared name is an error, never an implicit create**, in both the CLI and MCP: a typo would silently open a second file and split one history in half.
- **Closing an entry is a new EVENT, never an edit** (0.36.0): `Incident.Resolves []string` closes earlier entries (`StillOpen` = no own `fix` AND not resolved later); an unknown `resolves` id is REJECTED before the write; ids are DERIVED (`incidentID`), so pre-existing lines are closable. (history: docs/design-log.md)
- **Ordering**: entries read newest-first; an entry whose `ts` does not parse sorts LAST; `JournalStats.First/Last` come off the PARSED instant. (history: docs/design-log.md)
- **The cost average divides by `Costed`, not `Total`** - entries that recorded a cost. Dividing by the total would make a subsystem look CHEAPER the more often someone skipped the field, i.e. exactly backwards.
- **Surfaces**: `pm journal list|show|add|stats` (CLI, `--project` flag) and `pm_journal_add`/`pm_journal_list` (MCP); add reports back the recurrence its entry produced; stats travel WITH the entries in `pm_journal_list`. (history: docs/design-log.md)
- **`pm_context` / `pm context` get COUNTS ONLY**, never content - the same deliberate rule as the executor profile pointer (0.28.1, when `pm_context` was measured at 62k chars). A journal grows without bound and its readers are the sessions about to touch that subsystem, not every session. A project with no journals declared gains no key at all.

## Executor (`pm work` / `pm run-epic`) — autonomous task execution

Runs pm tasks/epics via **isolated headless `claude -p` workers** (implement → test → review → verify), so a multi-subtask epic executes without blowing one session's context. (history: docs/design-log.md)

- **`pm work [project] <task>`** (`internal/cmd/work.go`, `work_prompt.go`, `work_git.go`) - the ATOM: one fresh `claude -p` in the project dir, inner loop on one task, returns `{status,summary,branch,commits,unresolved}`. Standalone -> draft PR; `--epic` -> commit only. `planWork` (assemble, no side effects) + `executeWork` (run + record); `--dry-run` prints prompt+argv without spending tokens. Flags: `--model` (opus), `--max-turns` (150), `--timeout` (60m), `--yolo`, `--allow-dirty`, `--additional` (+ `--slot N`, `--base`). (history: docs/design-log.md)
- **`pm run-epic [project] <tracker>`** (`internal/cmd/run_epic.go` + `run_epic_sub.go`) - the MANAGER: side-effect-free `planEpic` (what `--dry-run` prints) + `executeEpic`; one `driveSubFlow` drives a sub in both modes, the mode differences live in the `subFlow` hook struct. Creates `epic/<tracker>`, drives ready subs sequentially by `Order`, each on `feat/<slug>` off the integration branch, merges back `--no-ff` on verify-green -> `done_status`. Blocked/failed/conflict -> park on `waiting` + continue; reasons bubble to the parent's `## Manager Notes` (`recordSubFeedback`). Re-entrant (skips merged/done); ends with ONE draft epic->main PR; never merges to main, never closes the parent. (history: docs/design-log.md)
- **`depends_on` gate** (`unmetDeps` in `run_epic.go`): a sub runs only when every listed sub is `merged`/`done`; an unmet dep SKIPS the sub (no worker, stays on its ready status - a re-run picks it up), unlike a genuine failure (parked on `waiting`). Opt-in; settable via MCP; shown in `--dry-run`. (history: docs/design-log.md)
- **`mode: auto | manual` gate** (`classifySub` in `run_epic.go`): `manual` = a PERMANENT human gate - skipped on EVERY run (no worker, status untouched, distinct `manual` outcome); the human does the work and moves the sub to `done_status` themselves; later auto subs gate on it via normal `depends_on`. Only lowercase `auto`/`manual` are valid (`storage.ValidateMode`); shown as `[MANUAL]` in `--dry-run`. (history: docs/design-log.md)
- **`model` per-sub override** (0.21.1): a sub's `model:` frontmatter beats the run-level `--model` in `pm run-epic`; in `pm work` an explicitly passed flag wins (`cmd.Flags().Changed`). Empty = inherit. Reviewers are independent of it (`executor.review_model`). (history: docs/design-log.md)
- **Hook bypass + lost results** (0.36.3): **`pm worker-guard`** (hidden command) rides on every worker as a PreToolUse hook via `--settings` - in `--yolo` too - blocking hook-bypass forms (`--no-verify`/`-n`, `core.hooksPath`, `HUSKY=0`, `rm`-ing hooks) with an exit-2 message naming the legitimate move; it FAILS OPEN on an unreadable payload. `parseWorkerOutput` falls back to the worker transcript when the envelope has no structured result. The verify phase's bound command IS the project's full validation for the worker - never swapped for the one named in the repo's docs. (history: docs/design-log.md)
- **Liveness = pid + process START TIME** (0.37.1, `internal/storage/process.go`): `ProcessAliveSince(Stamp)` - a process started BEFORE the lock's stamp is the writer, one started after is a recycled pid. EPERM counts as ALIVE; missing info degrades to bare liveness, never to "dead"; 5s grace. (history: docs/design-log.md)
- **`.git/` is not writable by ANY tool** (0.37.1): a SECOND PreToolUse matcher (`Write|Edit|MultiEdit|NotebookEdit`) judges `tool_input.file_path`; the bash patterns cover in-place sed, `tee` and redirects; the protected path is the whole of `.git/` (`core.hooksPath` lives in `.git/config`); reads stay allowed. (history: docs/design-log.md)
- **Commit-message prose is stripped before the guard matches** (0.37.1, `stripMessagePayload`): the payload of `--message`/`-m`/`-am` is blanked (never crossing `;`/`&&`/`|`), so prose about `-n` passes while a trailing `--no-verify`/`-n` AFTER the message stays blocked. (history: docs/design-log.md)
- **A dead worker says what killed it, and an account wall stops the run** (0.37.0): without an envelope, `workerLastWords` reads the last assistant message from the worker transcript (tee'd stderr as fallback); `accountWallReason` matches account-level phrases -> sub result **`aborted`**, the manager STOPS, the aborted sub returns to its ready status (never `waiting`), later subs are recorded `skipped` with a note; an unrecognised wall behaves as an ordinary failure. (history: docs/design-log.md)
- **Review policy lives in the harness, not the prompt** (0.38.0, `review_cap.go`/`review_packet.go`): pm's PreToolUse hook decides and REFUSES a non-compliant reviewer spawn. Count: `reviewerCap` from the production diff - `<=2` files/`<=50` lines -> 1, `<=10`/`<=400` -> 2, else 3, per round (tests/lockfiles/generated excluded from the COUNT only). Model: `executor.review_model` (default **opus**), independent of the run's `--model`. Packet: `buildReviewPacket` attaches the whole diff (>48kB -> `--stat` + whole files); reviewers have NO Bash. Rounds: `executor.fix_rounds` (default 2); a further round only after a valid finding. Matcher `Agent|Task`; nested spawns refused; `updatedInput` carries the RAW tool input; degrades to allow-and-record. `storage.ReviewTelemetry` records what the WORKER asked for. Budget: `reviewerToolBudget` (25) Read/Grep/Glob calls per `agent_id`, then the guard refuses ("finalize your report"; spawns/StructuredOutput never blocked); refusals = `tool_denied` in telemetry. (history: docs/design-log.md)
- **Gate G2** (0.38.0): the cheap reviewer clears bugs it should raise - in an A/B replay of two real bugs, sonnet examined both and argued them away, opus reported both; hence `review_model` stays opus. Re-run the experiment when the harness or model generation changes. (history: docs/design-log.md)
- **A document is not priced like code** (0.39.0): a doc-only diff (EVERY changed path has a prose extension - closed list, decided by extension never by path, computed over every changed path) gets **1 reviewer and 1 round** (`effectiveFixRounds` only ever LOWERS), with a check-the-claims-against-the-repo brief (`reviewDocPacketHeader`) instead of the adversarial-bug one; anything unclassifiable falls back to the code regime. (history: docs/design-log.md)
- **Worker gate economics** (0.36.2): review sizing counts PRODUCTION files only (tests/lockfiles/snapshots/generated excluded from the count, never from the reviewed diff); scoped lint is ONE autofix pass, never check->fix->recheck; never split one self-contained change across commits for tidiness (hooks bill per commit). (history: docs/design-log.md)
